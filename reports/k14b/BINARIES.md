# Где лежат бинарные артефакты K-14

В git их НЕТ: `.gitignore` исключает `*.npz`, и решено это правило не обходить.
В индексе остаются манифесты и логи — они несут отпечатки, по которым файл
можно опознать, но не сам файл. Это записано здесь, чтобы отсутствие бинарников
не выглядело упущением: они хранятся на вычислительном узле.

## Расположение

Узел: кластер, контейнер `avla_malinin_aa`, корень `/home/malinin_aa/Adaptive_VLA`.

| Файл | Путь | sha1[:12] | Размер |
|---|---|---|---|
| Канонический кэш целей q1 | `data/k14b/q1_cache.npz` и `reports/k14b/q1_cache.npz` | `9061f0da0dd3` | 2.7 МБ |
| Метки оракула, канонический режим | `reports/k14a/oracle_cache_cuda0.json.labels.npz` | см. `labels_sha1` в `oracle_cache_cuda0.json` | 1.68 МБ |
| Метки оракула, второй режим | `reports/k14a/oracle_cache_cpu.json.labels.npz` | см. `labels_sha1` в `oracle_cache_cpu.json` | 1.68 МБ |

Отпечатки записаны в `q1_cache.manifest.json` (`labels_sha1`, `q1_sha1`,
`rows_sha1`) и в артефактах оракула (`labels_sha1`). Подмена файла обнаруживается
сверкой, даже если самого файла нет в истории.

## Чем это ограничивает

Проверить утверждения, опирающиеся на содержимое массивов, вне кластера нельзя.
Конкретно: два перевернувшихся токена q2 (§42) и побитовое совпадение целей q1 с
оракулом подтверждаются по отпечаткам, но не пересчитываются независимо.

## Как восстановить

Кэш целей q1 детерминированно воспроизводим в каноническом режиме:

```
python experiments/k14b_build_q1_cache.py --device cuda:0 \
  --oracle reports/k14a/oracle_cache_cuda0.json --out data/k14b/q1_cache
```

Построитель отказывается работать при несовпадении данных, кодека, устройства
или отпечатков K-11b с теми, что записаны в артефакте Gate 2, и сверяет
полученные метки с оракулом побитово. Поэтому совпадение `sha1 = 9061f0da0dd3`
при повторном построении означает, что восстановлен именно тот файл.

Метки оракула воспроизводятся `experiments/run_k14a.sh` на двух устройствах.

## Если решение изменится

Варианты долговечного хранения, от которых отказались: Git LFS; хранилище
объектов с URI и отпечатком; принудительное добавление конкретного файла через
`git add -f`. Последнее дешевле всего — 2.7 МБ для кэша целей, — и к нему стоит
вернуться, если артефакт понадобится вне кластера.
