# K-14: что берётся из K-8, что заменяется, что новое

Инженерный артефакт Stage 0. Составлен по коду, не по памяти: `depth_rvq_vla.py`
(384 строки), `k8a_progressive_selftest.py`, `k8b_progressive_train.py`
(714 строк), `k8c_direct_action_probe.py` (525 строк).

## Чем кончился K-8

`q0` сошёлся к 25.4–26.5% против 87.3% у полной глубины; Fast застрял на 0.1386
при цели 0.0500. K-8c отдельно разделял две причины — нет информации о движении
на 12-м слое, либо цель «угадать индекс из 2048» плохо к ней приспособлена.

K-14 ставит вопрос иначе и потому не наследует постановку: `q0` **уже работает**
(Joint12, `fast12` 66.67% успеха в K-13c), и проверяется не «можно ли выучить
ранний выход», а «можно ли уточнить работающий черновик».

## Переиспользуем

| Что | Откуда | Почему без изменений |
|---|---|---|
| Сегментированный проход по слоям | `depth_rvq_vla.py` | Проверено по `bar.py`: один цикл, `_shared_attention_forward` ведёт обе башни вместе, счёт слоёв по `input_layernorm`, а не по `layer.forward` |
| `CodeFeedback` с нулевой проекцией и единичным вентилем | `depth_rvq_vla.py` | Обнулять и проекцию, и вентиль нельзя — обе производные обращаются в ноль и ветвь не обучается никогда |
| `straight_through` для мягкого пути назад | `depth_rvq_vla.py` | Нужен, чтобы ошибка q2 и действия могла обучать среднюю голову |
| Применение нормы на КАЖДОМ выходе | `depth_rvq_vla.py` | В зонде K-7c ранние глубины снимались без нормы, а `after_24` с ней — ранние недооценивались |
| Загрузка данных и батчинг | `k8b` | Не является предметом исследования |
| Каркас сохранения и продолжения — только КАРКАС | `k8b` | Формат чекпойнта и проверка при продолжении заменяются: нужны `stage`, `variant`, маска feedback, точное множество обучаемых имён и отпечатки замороженных модулей. Строгая схема — новое, переиспользуется лишь механика записи |

## Заменяем

| Что было в K-8 | Что в K-14 | Почему |
|---|---|---|
| `q0` обучается вместе с остальными | `q0` заморожен побитово (Joint12) | Иначе смешаны два вопроса: качество раннего выхода и польза позднего уточнения. K-14 изолирует второй |
| Статические цели: `q1*`, `q2*` — истинные коды | Условные: `q1* = Q1(z_e − E0[q0hat])`, `q2*` от **фактического** `q̂1` | Измерено (§42): условная цель лучше статической на 31.9%, расходится с ней на ~60% позиций. K-8 учил головы попадать в метки, не компенсирующие ошибку префикса |
| Совместное обучение всех уровней | Последовательное: q1, затем q2 при замороженном q1 | Устраняет движущуюся мишень q2 |
| LoRA в action expert (9.3 млн параметров) | Backbone заморожен целиком; обучаются только поздние нормы, головы и feedback | Иначе непонятно, помогло пространство кодов или дополнительная адаптация. LoRA — возможная абляция ПОСЛЕ frozen-варианта |
| Одна норма на все глубины | `norm18` и `norm24` раздельно, инициализация из исходной финальной нормы | Норма Joint12 обучена читать `h12`; применять её к `h18`/`h24` — тот же класс ошибки, что уже ловился в HiCoRA |
| Своё разбиение | Разбиение по эпизодам K-11c: сид 61, доля 0.4, те же `val_sel`/`val_confirm` | Подтверждающая половина обязана быть одной и той же во всех работах |
| Цель — `D(E0+E1+E2)` от истинных кодов | Ошибка считается и против предела кодека, и против **настоящего действия** | При опоре только на реконструкцию ошибка самого кодека тождественно нулевая и из анализа исчезает |
| Общий whitelist обучаемых весов | Три точных множества по этапам плюс ПОУРОВНЕВАЯ маска исполнения feedback, fail-closed, без режима по умолчанию | Общий список размораживал оба поздних уровня сразу. Отдельно: выбора весов мало — вариант `no_feedback` должен ОБХОДИТЬ модуль в forward, иначе после загрузки ненулевого чекпойнта feedback заморожен, но действует |

## Новое

| Что | Зачем |
|---|---|
| Оракул Gate 2 до обучения (`k14a`) | Дешёвая фальсификация: если книг не хватает, подбирать learning rate бессмысленно. Пройден: 73.3% при пороге 25% |
| Канонический кэш `q1*` (`k14b`) | Метка выбирается ближайшим кодом, и у части позиций два кода почти равноудалены (разрыв 5e-08). Пересчёт в тренере дал бы двум seed разные задачи |
| Gate 4 с формулой захвата `C = (E_A0 − E_model)/(E_A0 − E_oracle) ≥ 0.20` | Порог записан до обучения; при текущем оракуле это RMS ≤ 0.132025 |
| `stage`/`variant` и отпечатки замороженных модулей в чекпойнте | Продолжение обязано проверяться, а не подразумеваться |
| Контроли `dynamic+no_feedback` и `static+feedback`, по два сида | Механизм заявляется только после них; при провале main ветка останавливается, no-feedback становится отдельной зарегистрированной salvage-гипотезой |
| Два прогона называются **training/data-order seeds** | Поздние головы инициализируются детерминированно (копия `action_lm_head`, нулевой feedback, копия исходной нормы) — это не независимые инициализации |
| Горизонт 8 во всех метриках | Робот исполняет первые 8 позиций чанка из 16; улучшение в хвосте до него не доходит |

## Что из K-8 переиспользовать НЕЛЬЗЯ

Численные результаты K-8 (25.4–26.5%, 0.1386) — только описательно. Для любой
таблицы нужен одинаковый текущий чекпойнт, данные и режим точности; после §39
смешивать прогоны разных режимов запрещено.
