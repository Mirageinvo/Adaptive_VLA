# RAS-DF-VLA — Reversible Active-Set Discrete Flow VLA

Рабочий план. Прежний план по RC-HDF закрыт и перенесён в
`PLAN_RC_HDF_ARCHIVED.md`; числа оттуда не цитировать.

## Гипотеза

> После изменения текущего плана полезность повторного пересчёта сосредоточена
> в небольшом, нелокальном и зависящем от состояния множестве временных
> action-позиций. Нужно научиться причинно выбирать это множество ДО дорогого
> прохода и действительно вычислять только выбранные позиции.

`reversible` означает, что позиция не фиксируется навсегда: на одном шаге
refinement она может быть неактивной, на следующем снова войти в active set.

**Пока не оправдано.** На датасете B0 обратимая жадная траектория использует
REMOVE в 0.24% случаев при средней длине 3.32: при бюджете ≤4 и support около
шести откатываться почти никогда не нужно. Механизм остаётся в коде, но из
названия метода слово убирается до появления измеренной пользы — его место в
фазе D, где шагов потока много и позиция может устареть между шагами.

## Что установлено (feasibility evidence, не результат модели)

Всё получено оракулом, который копирует коды из `z_ref`; ни обучаемого router,
ни настоящего sparse refiner пока нет. Подробности — `FINDINGS.md` §7б, §7в.

Числа приводятся по датасету B0 (16000 вмешательств, test), потому что именно
на нём оценивается router. В скобках — фаза A (96 наблюдений); расхождение
0.02–0.04 объясняется другой длиной паддинга и другой выборкой, см. §7д.

| величина | значение |
|---|---|
| позиций меняется полным fine-пересчётом | 4.74 из 16 |
| точный оракул, K≤4 | **0.902** (0.93) |
| жадный оракул, K≤4 | **0.842** при офсете eval (0.881 при офсете 3) |
| независимое ранжирование по истинным gains | **0.740** (0.79) |
| **лучший причинный baseline** | **0.295** при офсете eval (0.345 при офсете 3) |
| случайный выбор четырёх, 20 сидов | **0.133** (0.18) |
| 16→4 внутри BAR | 1.03× на проход, сквозного выигрыша нет |
| вредных позиций внутри changed-support | 32.5% |
| лучший набор меньше четырёх | 29% случаев |
| обратимость (REMOVE в траектории) | 0.24% — не оправдана |

Непрерывные окна и два сегмента недостаточны (тест эквивалентности провален,
верхняя граница отставания 0.042 при пороге 0.03). Отдельный action-only
refiner не проверен.

## Чего заявлять НЕЛЬЗЯ до дополнительных тестов

- «Функция ремонта доказанно субмодулярна».
- «Синергии между позициями нет».
- «Последовательный router обязательно превосходит one-shot».
- «Четырёх позиций всегда достаточно».
- «Разреженный refinement уже ускоряет VLA».
- «Offline action error переводится в success rate».
- «Структура с искусственной BAR-интервенции сохраняется на траектории потока».

Корректная текущая формулировка:

> Выбранные позиции в среднем демонстрируют избыточность, а последовательный
> оракул избегает взаимозаменяемых позиций. Субмодулярность и предсказуемость
> active set требуют отдельных тестов.

## Главный ближайший вопрос

> Можно ли из строго причинных признаков выбрать не более четырёх позиций так,
> чтобы закрыть существенно больше 0.295 и приблизиться к оракульным 0.842, не
> выполняя заранее плотный fine-проход?

Протокол зафиксирован: левый паддинг и `pos_offset = 4`, как в
`scripts/eval_libero.py`. Прежние замеры шли на офсете 3 — см. `FINDINGS.md` §7е.

До ответа полноценную flow-модель не обучать.

**Прежние ворота фазы 1 «violation mass ≤ 5%» отменены**: метрика непригодна —
сумма по 12720 тройкам, делённая на один скалярный выигрыш, имеет произвольный
масштаб. Заменена долей нарушений среди содержательных троек, порога не
требующей.

**Решение о продолжении B1 опирается на измеренный разрыв**, а не на
субмодулярную теорию: причинный baseline 0.345, независимый оракул 0.740,
жадный 0.881, точный 0.902 — всё на test датасета B0. Разрыв 0.345 → 0.881 и
есть предмет фазы B.

Планка высокая, и это надо понимать заранее: порог «продолжать» (≥0.70) требует
восстановить 95% оракульного одиночного ранжирования из признаков, доступных до
плотного прохода. Если он не берётся, вывод «признаков недостаточно» надо
отличать от «полезность непредсказуема» — через абляции признаков.

Резервная ветка — adaptive NFE / early stopping плотного action-only flow.
Переходить к ней при провале ворот 4, 5 или 7. Начинать с оракульного
minimal-NFE теста, а не сразу с halting head.

Отложенная ветка — adaptive temporal tokenization. Сейчас данных за неё нет:
полезные позиции разбросаны, multi-segment не эквивалентен произвольному
набору.

## Закрытые ветки

- residual suffix projection как самостоятельная новизна;
- sparse refinement внутри существующего BAR;
- фиксированные временные окна;
- multi-segment router как эквивалент произвольного множества;
- экономия за счёт маскирования выходных токенов плотной модели.

## Правило причинности для router

**Можно:** observation/VLM context; старые coarse и fine токены; `lg_before`;
энтропия и запас top1−top2 из `lg_before`; предложенная правка `u → v`;
`e(u)`, `e(v)`, `e(v) − e(u)`; текущая кумулятивная латента; временная позиция;
история предыдущих шагов refinement.

**Нельзя:** `lg_after`; JS между `lg_before` и `lg_after`; fine-коды `z_ref`;
`h_ref`; датасетное действие; результат полного пересчёта.

Значение нового coarse-кода `v` использовать можно — в настоящей модели это уже
предложенное исправление.

## Инженерные правила

Каждый эксперимент обязан: фиксировать commit hash, config и seed; сохранять
episode ID для split; складывать сырые результаты в NPZ; содержать синтетический
self-test с известным ответом; использовать кластерный бутстрап по эпизодам;
отделять непрерывную ошибку действия от схвата; явно маркировать оракульные и
deployable признаки; различать измеренный runtime и аналитическую
экстраполяцию; сравнивать методы при равном compute; не менять метрику после
просмотра результата; не обновлять `FINDINGS.md` до проверки кода и повторного
запуска.
