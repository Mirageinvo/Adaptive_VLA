# K-27: память дерева о собственном плане (parents_mem24)

План: `K27_Tree_Plan_Memory_Agent_Plan.md` (28.10.2026). Пакет A — CPU-часть.

## Что это

`parents_mem24` — исторический parents24 (K-22 seed 0, K-23 seed 1) с
**замороженными** весами и одним новым обучаемым модулем памяти
(`self.mem`, 403 073 параметра при H = 768). Между вызовами политики
сохраняется снимок собственного дерева: hidden 4 корней и 8 средних после
слоя 24 (до нормы), их интервалы, веса W0/W1, собственный предсказанный чанк
[20, 7] и state11 (~38 КБ на среду во float32). На следующем вызове
интервалы сдвигаются на фактически исполненные k шагов (обычно 8), мёртвые
узлы маскируются, и текущее дерево дважды читает остаток старого:

- после слоя 8 — текущие корни против старых корней
  (`softmax(S + log перекрытия)`);
- после слоя 16 — текущие средние против старых средних, с prior от
  соответствия корней (`0.9·A0[j//2, m//2]/d_m + 0.1·U`).

Обновление — gated residual `h + has_overlap · g · Wo(C)` (Wo = 0,
gate = 0.1 при инициализации). Новый чанк всегда строится из актуального
наблюдения; прошлые команды не копируются и не растягиваются.

## Отличие от K-26

| | K-26 | K-27 |
|---|---|---|
| Новая информация для узла | визуальные токены текущего кадра | собственный план прошлого вызова |
| База | обучение с нуля от BAR (эксперт, LoRA, новые) | замороженный обученный parents24 |
| Обучаемое | всё прежнее + router (0.72 млн) | только память (0.40 млн) |
| Контроль | новый flat_attn24 и старые parents24/flat24 | исторический parents24 того же сида (memory off = он же побитово) |
| Обучение | 1000 + 8000 обновлений | 2000 обновлений, цепочки 2–3 наблюдения с шагом 8 |
| Состояние между вызовами | нет | снимок дерева на среду (MemoryBank) |

Визуального router K-26, MR/cond-readout, RL и нового токенизатора нет.

## Ограничения первой версии

- Мягкое повторное использование контекста оставшихся узлов: все текущие
  узлы проходят все 24 слоя. Нет жёсткого копирования ветвей и пропуска
  вычислений — это НЕ выборочный пересчёт поддеревьев и не ускорение.
- Гейт — не вероятность успеха подцели; истечение интервала не означает её
  достижения; отдельного классификатора захвата, world model и
  дополнительных потерь нет.
- Обучение на собственных прогнозах при наблюдениях демонстраций
  (truncated: снимки detach), а не восстановление после собственных ошибок
  в среде.
- Чтений на листьях нет.

## Файлы пакета A

- `k27_memory.py` — сдвиг, перекрытия, сводка собственных команд, признаки
  узлов, сопоставление (корни, средние с prior), модуль памяти, MemoryBank
  (env_id/эпизод/шаг; reset, новый эпизод, k ≥ 20, часы назад — отказ).

- `k27_model.py` — K27 поверх K-22 (две точки чтения, снимок, memory off).

## Замечание о точном совпадении

`memory off` воспроизводит parents24 побитово при той же заморозке
параметров. На CPU сам `requires_grad` меняет ядро Linear на 1 ULP, поэтому
сравнение ведётся с замороженной базой — так же, как в руке SR K-22
(`k22_policy` выключает градиенты у всех параметров).

## Пакет B

- `k27_train.py` — загрузка parents24 сида (SHA файла, отпечаток весов,
  режим и seed контракта), полная заморозка, обучение только `mem.*` на
  цепочках собственных прогнозов (ранние вызовы eval/no_grad, потеря только
  на текущем), real-check (оба сида: база = источнику, memory off и нулевой
  Wo = замороженный parents24; seed 0: micro 8/16/32 на цепочках из 2 и 3
  наблюдений, путь градиента через GradScaler), fitcheck (64 цепочки, 200
  обновлений, снижение L ≥ 10%), обучение 2000 обновлений с возобновлением.
- `k27_policy.py`, `k27_harness.py` — учёт сред обёрткой `utils.get_envs`
  (reset -> новые эпизоды, step -> исполненные шаги), MemoryBank, журнал и
  debug-фрагмент.
- `k27_protocol.py` — подготовка, планы (memory-off smoke и основной SR),
  проверка журнала с CPU-пересчётом A0/A1, сверка memory off с закреплёнными
  блоками parents24 (offcheck).
- `k27_analyze.py`, `k27_latency.py` (cold и steady), `k27_run.sh`.

GPU-часть — после окончания K-26:

```bash
bash experiments/k27_run.sh real-check cuda:0
bash experiments/k27_run.sh fitcheck cuda:0
nohup bash experiments/k27_run.sh run cuda:0 > /dev/null 2>&1 &
```
